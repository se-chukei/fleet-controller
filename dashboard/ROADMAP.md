# Fleet-Controller Integration & Client APK Development Roadmap

This guide provides a comprehensive, step-by-step roadmap to go from the current **fleet-controller web dashboard** to a fully running, physical hardware test environment.

---

## 🗺️ Architectural Terminology

To ensure consistency across the development lifecycle, we use the following terms:
1. **`fleet-controller` (Dashboard)**: The React-based web user interface (this app) used to monitor, configure, and force-control the fleet.
2. **`data bridge`**: The central backend orchestration service (Express/Node) that receives webhooks from TVU and sends state directives (`STREAM` or `STANDBY`) to the Android TV clients. During local testing, **your Mac acts as the stand-in Data Bridge**.
3. **`fleet-controller-client` (Android Client APK)**: The background application service written in Kotlin/Java that runs on the physical Android TV / Google TV units in venues, playing the streams using libVLC.

---

## 🛠️ Step-by-Step Breakdown: Building the Client APK (`fleet-controller-client`)

To get a testable APK running on your Android TV Streamer, follow these detailed steps to build **`fleet-controller-client`**:

### Step 1: Initialize the Android Studio Project
1. Open Android Studio on your Mac.
2. Select **New Project** -> **Android TV** (or **Phone and Tablet**) -> **Empty Activity** (or **No Activity**).
3. Set the project properties:
   - **Name**: `fleet-controller-client`
   - **Package name**: `com.se_chukei.fleetcontroller`
   - **Language**: `Kotlin`
   - **Minimum SDK**: `API 26 ("Oreo"; Android 8.0)`
4. Click **Finish** and wait for Gradle to finish downloading initial project files.

### Step 3: Add LibVLC and Permissions without Breaking Gradle
To prevent Gradle sync errors, **do not replace the entire file**. Simply make two small edits to your generated files:

1. **Edit `build.gradle.kts (Module :app)`** (located under `Gradle Scripts`):
   - Make sure the file starts with the `plugins` block so Gradle recognizes the `android { ... }` configuration:
     ```kotlin
     plugins {
         alias(libs.plugins.android.application)
         alias(libs.plugins.kotlin.android)
     }
     ```
     *(If `alias` causes an error, use `id("com.android.application")` and `id("org.jetbrains.kotlin.android")` instead).*
   - Check that `minSdk = 26` (inside `defaultConfig`).
   - Scroll down to the `dependencies { ... }` block at the bottom and **add this single line**:
     ```kotlin
     dependencies {
         // ... keep existing lines generated by Android Studio ...
         // Note: Having 'platform(libs.androidx.compose.bom)' in implementation AND androidTestImplementation is normal!
         
         // Native Video Playback (LibVLC for RTSP/UDP stream decoding)
         implementation("org.videolan.android:libvlc-all:3.6.0") // or 3.7.5
     }
     ```
   - Click **"Sync Now"** in the top banner that appears in Android Studio.
   > 💡 *Note: If Android Studio temporarily hid your `src/` or `java/` folders, clicking "Sync Now" will immediately bring them back as soon as Gradle sync succeeds!*


2. **Edit `AndroidManifest.xml`** (located under `app` -> `manifests`):
   - Add these permissions right above the `<application>` tag:
     ```xml
     <!-- Network access -->
     <uses-permission android:name="android.permission.INTERNET" />
     <uses-permission android:name="android.permission.ACCESS_NETWORK_STATE" />
     
     <!-- Prevent Android from putting player thread to sleep -->
     <uses-permission android:name="android.permission.WAKE_LOCK" />
     
     <!-- Auto-boot app immediately when the device powers on -->
     <uses-permission android:name="android.permission.RECEIVE_BOOT_COMPLETED" />
     
     <!-- Keep the background player running persistently -->
     <uses-permission android:name="android.permission.FOREGROUND_SERVICE" />
     <uses-permission android:name="android.permission.FOREGROUND_SERVICE_MEDIA_PLAYBACK" />
     ```

### Step 3: Implement the Core Foreground Service (`FleetService.kt`)
Android TV units must play feeds indefinitely. To prevent the OS from killing the playback thread, wrap the player in a persistent Foreground Service with an active sticky notification.
1. Create a `FleetService` class extending `android.app.Service`.
2. Implement a start sticky command (`START_STICKY`) which spawns a system tray notification.
3. Acquire a standard CPU WakeLock in `onCreate()` to ensure decoding never sleeps:
   ```kotlin
   val wakeLock = (getSystemService(POWER_SERVICE) as PowerManager).run {
       newWakeLock(PowerManager.PARTIAL_WAKE_LOCK, "FleetController::CpuWakeLock").apply {
           acquire(14400000L) // 4 hours timeout to prevent Android Studio warning
       }
   }
   ```

### Step 4: Create the Polling State Client
Each `fleet-controller-client` unit will continuously poll the central Data Bridge to fetch the current stream state, using a randomized jitter to prevent thundering herd problems:
1. Spawn a background coroutine or thread that runs in a loop.
2. Every 2 seconds (plus 1-3 seconds of randomized jitter delay), perform an HTTP GET request to `http://<data-bridge-ip>:8080/api/state`.
3. Parse the JSON response: `{"state": "STREAM", "streamUrl": "rtmp://..."}` or `{"state": "STANDBY", "streamUrl": "rtmp://..."}`.
4. If the state or URL changes, immediately direct your local VLC Player thread to switch URIs to the newly provided `streamUrl`.

### Step 5: Implement Native VLC Player & Rendering Layer (`MainActivity.kt`)
1. In your Main Activity XML, define a simple `org.videolan.libvlc.util.VLCVideoLayout` filling the entire screen.
2. Initialize `LibVLC` options in Kotlin:
   ```kotlin
   val args = ArrayList<String>().apply {
       add("-vvv") // Verbose logs
       add("--live-caching=1500") // 1.5 seconds network buffer
       add("--clock-jitter=0") // Reduce latency jitter
       add("--clock-synchro=0")
   }
   val libVLC = LibVLC(context, args)
   val mediaPlayer = MediaPlayer(libVLC)
   ```
3. Bind the media player to the XML `VLCVideoLayout` container so video plays natively:
   ```kotlin
   mediaPlayer.attachViews(vlcVideoLayout, null, true, false)
   ```

### Step 6: Create the Self-Healing Watchdog
To protect decoders against hardware overheating or C++ native crashes (libvlc thread locks):
1. Spawn a background thread checking the `MediaPlayer.Event.Playing` timestamp once every 5 seconds.
2. If VLC stops rendering frames or reports `MediaPlayer.Event.EncounteredError`:
   - Attempt 1: Re-initialize the `MediaPlayer` instance in-memory.
   - Attempt 2 (Fatal lockup): Call `Runtime.getRuntime().exec("reboot")` (requires system/root appliance permissions) or force-quit the process to trigger a clean Android OS relaunch on boot.

## 💻 How to Test & Debug Locally using your Mac as the Data Bridge

Once you have prepared the code, you can easily test the entire ecosystem right from your desk:

### 1. Connect and Sideload the APK to Android TV
1. Turn on **Developer Options** and enable **USB Debugging** on your Google TV / Android TV unit.
2. Connect the Android TV to your Mac (via USB-C or ADB-over-Wi-Fi).
3. On your Mac, run:
   ```bash
   adb devices
   ```
4. Build the release APK in Android Studio and sideload it to the device:
   ```bash
   adb install -r path/to/app-release.apk
   ```

### 2. Set Up the Tailscale Mesh
1. Install **Tailscale** on both your Mac and the Android TV unit.
2. Sign both devices into the *same* Tailscale account (tailnet).
3. Find their Tailscale IPs (e.g. your Mac is `100.80.90.10` and the Android TV is `100.120.10.15`).

### 3. Start the Data Bridge on your Mac
1. Save the **Express Server Code** (copyable from the new *TVU Webhook & Data Bridge Simulator* dashboard tab) as `bridge.js` on your Mac.
2. Install Express in your Mac terminal:
   ```bash
   npm install express
   ```
3. Start your local Mac Data Bridge:
   ```bash
   node bridge.js
   ```

### 4. Trigger and Verify Webhook State Synchronization
Now, you are ready to simulate real TVU events:
* **Simulate Live Stream Start**:
  Run this command in your Mac's terminal to simulate TVU starting a live stream (the Data Bridge should store this state):
  ```bash
  curl -X POST http://localhost:8080/api/webhook/tvu \
    -H "Content-Type: application/json" \
    -d '{"event": "stream_start"}'
  ```
  *Expectation*: Your Mac's Express app receives the hook and updates its internal state to "STREAM". Within ~2-5 seconds, the Android TV's `fleet-controller-client` polls the Data Bridge, notices the new state, and switches VLC from standby to the high-quality RTMP event feed.

* **Simulate Live Stream Stop**:
  ```bash
  curl -X POST http://localhost:8080/api/webhook/tvu \
    -H "Content-Type: application/json" \
    -d '{"event": "stream_stop"}'
  ```
  *Expectation*: The Data Bridge state updates to "STANDBY". Upon its next polling interval, the Android TV unit sees the change and immediately switches video rendering back to the ambient background RTMP feed.

## 🚀 Next Steps / Production Transition

1. **Verify Local Playback Stability**: Let the Android TV unit decode the stream for 48 hours continuously under your local Mac's Data Bridge controller to test memory consumption and watchdog stability.
2. **Deploy the Production Data Bridge**: Once local tests are green, deploy your `bridge.js` to a cloud virtual machine (e.g., Google Cloud Run, AWS, or an on-premise server) with a fixed public IP.
3. **Register Webhook Destination**: Point the actual **TVU Broadcaster** admin dashboard's webhook output URL to `http://<your-production-server-ip>/api/webhook/tvu`.
4. **Appreciate the Dashboard Integration**: The new **TVU Webhook & Data Bridge Simulator** on your web dashboard is fully configured to help you test this exact routing logic from day one!
